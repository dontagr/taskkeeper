# Мой стек ИИ-инструментов

Шаблон для читателей книги **«Вайбкодер»**. Заполните под себя или скопируйте в свой репозиторий.

**Связанные файлы:** [vibe-journal.md](./vibe-journal.md) · [matrix-tasks.md](./matrix-tasks.md) · [Task keeper](../README.md)

Классы инструментов (A–E) — **глава 3** книги. Здесь — **ваши имена** и решения.

**Обновляйте:** при смене работы, подписки, политики; раз в квартал — блок «Ревью».

---

## Классы (напоминание)

| Класс | Что это | Обычно для |
|-------|---------|------------|
| **A** | Веб-чат с LLM | объяснения, черновики, brainstorm |
| **B** | IDE + ИИ (чат, edit, agent) | ежедневная разработка |
| **C** | CLI-ассистент | команды, скрипты |
| **D** | API / корп. боты / CI | команда, RAG по внутренним докам |
| **E** | Узкие продукты | review bot, test gen, security |

## Текущий стек (заполните)

| Роль | Класс | Инструмент | Для чего | Лимиты / план |
|------|-------|------------|----------|----------------|
| Основной dev | B | *(например: Cursor)* | код, agent, репо | |

| CLI | C | *(или —)* | | |

| Другое | E | | | |

**Правило:** 2–3 класса обычно достаточно; не дублировать одно и то же в пяти чатах.

## Политика компании / безопасность

Заполните по факту (если неясно — уточнить у security / лида):

- [ ] Можно ли отправлять **исходный код** во внешний LLM?
- [ ] Есть ли **корпоративная** альтернатива (on-prem, внутренний чат)?
- [ ] Нужно ли **указывать в PR**, что код с ИИ?
- [ ] Запрещено в промптах: секреты, PII, prod URL — да / нет
- [ ] Контакт / ссылка на политику: *(URL или «спросить у …»)*

См. **главу 5** книги (лимиты и приватность).

| Дата | Инструмент | Класс | Плюс | Минус | Вердикт |
|------|------------|-------|------|-------|---------|
| | | | | | оставил / отказался / заменил |

**Пример:**

| Дата | Инструмент | Класс | Плюс | Минус | Вердикт |
